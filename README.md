# STEP Series support

Support for the [STEP400](https://ponoor.com/docs/step-series/en/hardware/step400/) and [STEP800](https://ponoor.com/docs/step-series/en/hardware/step800/) stepper motor controllers by Ponoor Experiments: the forum, the documentation, and the configuration files.

## Questions and discussion → [Forum (GitHub Discussions)](https://github.com/ponoor/step-series-support/discussions)

Ask questions, report problems and suggest improvements in the **[Discussions](https://github.com/ponoor/step-series-support/discussions)** of this repository. English and Japanese are both welcome.

質問・不具合の報告・ご要望は、このリポジトリの **[Discussions](https://github.com/ponoor/step-series-support/discussions)** にお寄せください。日本語でも英語でもかまいません。

When you report a problem, these help: the board (STEP400 / STEP800), the firmware version, your `config.txt`, the OSC messages you sent, and what you expected to happen.

## What is in this repository

The repository started as the place for the forum and the configuration files. It now also holds the source of the documentation site and the tools that build it.

| Path | What | Edit by hand? |
|---|---|---|
| [`docs/`](docs/) | The pages of the documentation site (Markdown, Japanese in `docs/ja/`, English in `docs/en/`), images and PDFs. See [`docs/README.md`](docs/README.md) | Yes, except the generated blocks |
| [`spec/`](spec/) | The OSC command specification (`osc-commands.yaml`, checked against `osc-commands.schema.json`) and the Japanese glossary. **The single source** for the OSC reference pages and the Python library's command classes | Yes |
| [`configGenerator/`](configGenerator/) | Configuration templates, example `config.txt` files per motor, the generator script, and the browser configuration tool. See [`configGenerator/README.md`](configGenerator/README.md) | Yes |
| [`tools/`](tools/) | Scripts: page generation, checks, site build and upload, Python library generation (list below) | Yes |
| [`tests/`](tests/) | Tests of the generated pages, links, redirects and tools (`pytest`) | Yes |
| [`mkdocs.yml`](mkdocs.yml) | Site configuration (MkDocs + Material, navigation, languages) | Yes |
| [`mkdocs.preview.yml`](mkdocs.preview.yml) | The same site built for the trial URL (`/docs-preview/step-series/`, not indexed) | Rarely |
| [`overrides/`](overrides/) | Material theme overrides (the slot for the ponoor.com header) | Rarely |
| [`deploy/`](deploy/) | `.htaccess` files for the web server (redirects from the old WordPress URLs) | Generated by `tools/gen_htaccess.py` |
| [`.github/workflows/checks.yml`](.github/workflows/checks.yml) | CI: runs the checks below on every push and pull request | Rarely |
| `requirements-docs.txt`, `tools/requirements.txt` | Python packages for the site and for the tools | — |

Not in git (ignored): `site/`, `site-preview/` (build output), `wp_export/` (the export of the old WordPress pages, used once for the migration and for the redirect map), `claude_docs/` (working notes).

### Scripts in `tools/`

| Script | What |
|---|---|
| `generate.py` | Writes the OSC reference blocks in `docs/{ja,en}/reference/` and `docs/llms*.txt` from `spec/` |
| `validate_spec.py` | Checks `spec/osc-commands.yaml` against the schema; `--ja` also checks the Japanese terms |
| `spec.py` | Shared code that reads `spec/osc-commands.yaml` (used by the other scripts) |
| `check_firmware.py` | Compares the spec with the firmware source at a given tag |
| `build_site.sh` | `production` → `site/`, `preview` → `site-preview/` (runs `generate.py`, then `mkdocs build --strict`) |
| `deploy.sh` | Uploads a built site to the server (dry run unless `--apply`) |
| `gen_htaccess.py` | Makes `deploy/*.htaccess` from `docs/_redirects_map.md` |
| `mkdocs_hooks.py` | MkDocs hook: one search index per language |
| `gen_python.py`, `snapshot_python_api.py`, `migrate_python_docs.py`, `python_compat.yaml`, `python_templates/` | Generation and checks for the Python library (python-step-series) |
| `hooks/pre-commit` | Runs the spec and generation checks before each commit |

## How the documentation is made

```
spec/osc-commands.yaml ──tools/generate.py──▶ docs/{ja,en}/reference/*.md  (generated blocks)
                                              docs/llms.txt, docs/llms-full.txt
hand-written pages in docs/{ja,en}/ ─────────┐
                                             ├─ mkdocs build ─▶ site/ ── tools/deploy.sh ─▶ ponoor.com/docs/step-series/
mkdocs.yml, overrides/, docs/assets/ ────────┘
```

- The OSC reference is generated: to change a command's description, edit `spec/osc-commands.yaml` (both `en` and `ja`), not the page.
- Japanese is the top of the site; English is under `en/`.

## Building the site locally

```sh
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-docs.txt -r tools/requirements.txt
python tools/generate.py --defaults both --coverage
mkdocs serve                      # http://127.0.0.1:8000/
```

Full build: `tools/build_site.sh production` (output in `site/`).

## Checks

The same checks run in CI ([`checks.yml`](.github/workflows/checks.yml)):

```sh
pip install pytest                # once, in addition to the packages above
python tools/validate_spec.py --ja
python tools/generate.py --check --defaults both --coverage
python tools/gen_htaccess.py --check
pytest -q
mkdocs build --strict
mkdocs build --strict -f mkdocs.preview.yml
```

To run the spec and generation checks before every commit: `git config core.hooksPath tools/hooks` (once per clone).
